**Ask your agent "what did I decide last week?" and its memory has to know which week.** Hindsight now reads the dates in a question with [text2date](https://github.com/vectorize-io/text2date), a small model we trained for exactly this job. It gets the dates right far more often than the library we used before, it speaks 16 languages, and it knows when a question has no date at all.

## TL;DR

- **Recall finds the right time window far more often.** On Hindsight's own date tests, 98.7% right instead of 91.0%. On everyday English questions, 98.7% instead of 55.9%.
- **It stops inventing dates.** "She may have been right" used to search May. Questions with no date now get a date by mistake 1.1% of the time in English, instead of 24.4%.
- **16 languages**, including Chinese, Japanese, Korean, Arabic, Hindi and Thai, each tested on about 3,000 questions.
- **About 1 ms per question**, on the CPU, with numpy alone. The 10 MB model ships inside the package: no GPU, no download, no LLM call.
- **On by default** in the next Hindsight release. `HINDSIGHT_API_QUERY_ANALYZER=dateparser` switches back.
- **Open:** the model is [`hs-date-1`](https://huggingface.co/hindsight-ai/hs-date-1) and the 940k training questions are [`hs-date-1-data`](https://huggingface.co/datasets/hindsight-ai/hs-date-1-data), both MIT. Use it anywhere with `pip install text2date`.

## Why dates matter in memory

When you recall, Hindsight searches four ways at once: by meaning, by keywords, through the graph of people and things, and **by time**. If the question names a time ("last week", "in March", "上个月"), Hindsight turns it into a date window and looks for the memories from that window, spread across the whole period ([how recall works](/developer/retrieval#temporal-search)).

So the date step has to be right:

- **A wrong date hides the right memories.** If "last quarter" becomes nothing, or "the 90s" becomes today, the memories you wanted never reach the time search.
- **A made-up date adds noise.** "Remind me that April is allergic to penicillin" is about a person called April, not the month.
- **No date is safe.** When the question has no date, recall simply searches everything. That's why text2date says "no date" when it isn't sure.

## How Hindsight uses it

Nothing changes in how you call recall. On every recall, Hindsight:

1. Reads the question with text2date, on the day it was asked: your `question_date` if you pass one, in your own time zone, or today.
2. Takes the first time window the question names. "Compare May 2025 and June 2026" uses May 2025.
3. Hands that window to the time search, next to the other three.

A few rules keep it safe:
- If the question has no date, or only one end of a range ("before 2020", "from tomorrow on"), recall searches all of time, as before.
- If you already know the period (a date picker in your app), pass `temporal_window` and Hindsight skips the date step.
- The model gives a confidence for every answer. Below 0.5 it says "no date" instead of guessing.

**Speed.** One question takes 1.1 ms at the median (p99 2.1 ms). Under load it holds up better than dateparser did. With 32 recalls at once in one process, the date step's p99 is 55 ms instead of 302 ms, and it handles 2.6 times as many questions per second.

## How we trained it

**The model doesn't write dates. It writes what the question means.** "Last week" becomes `week -1`, "the past 6 months" becomes `last 6 month`, "三天前" (three days ago) becomes `day -3`, and "what is my wifi password" becomes `none`. Plain Python code then turns that meaning into dates, for the day the question was asked. The model never has to know how many days February has, or which day of the week it is. The calendar math is always right, and the model only learns language.

**The data: 940,000 checked questions.**
- An open LLM (Gemma 4) wrote everyday questions in 16 languages for random meanings: "a question about the week before last, in Korean", "a question with no date that mentions a product called Office 2019".
- Every question was checked: its meaning was turned back into dates and compared with what was asked. Questions without a date got a second opinion, because "may" and "June" are traps.
- Short search-box queries ("上个月 会议") came from templates, because LLMs write too politely.
- We then ran the model, collected the questions it got wrong, fixed their labels and trained on them again.
- Any question that also appears in a test set was removed from training.

**The model: tiny on purpose.** It's a byte-level transformer with 4.8 million weights: it reads the raw bytes of the question, so any script works without a vocabulary per language. One training run takes about six hours on a laptop. We trained it from scratch, then fine-tuned it a few times on gaps we found, then dropped the parts of the network that never switched on.

**One rule: no hand-written rules.** Whenever the model got something wrong, the fix was more training data, never an `if` in the code. That's how 16 languages stay manageable: adding a language is a data job.

**We checked it isn't memorizing our tests.** After many rounds of fixes, we trained it again from scratch on the same data. It scored within 1 to 2 points of the fixed model in every language, not just on Hindsight's tests.

## Limits

- **Whole days only.** "Yesterday at 3pm" gives yesterday.
- **No Diwali, Holi or other Hindu-calendar days yet**, and personal events ("my birthday") give no date.
- **Other languages** don't crash, but they aren't trained or tested.

## Try it

It's on by default in the next Hindsight release. To switch back:

```bash
HINDSIGHT_API_QUERY_ANALYZER=dateparser
```

Or use it on its own, in any Python project:

```bash
pip install text2date
```

```python
from datetime import date
import text2date

text2date.parse("what did I decide last week", anchor=date(2026, 11, 20))
# [DateRange(start=date(2026, 11, 9), end=date(2026, 11, 15))]

text2date.parse("上个月的会议", anchor=date(2026, 11, 20), tz="Asia/Shanghai")
# [DateRange(start=date(2026, 10, 1), end=date(2026, 10, 31))]
```

The code is on [GitHub](https://github.com/vectorize-io/text2date), the model on [Hugging Face](https://huggingface.co/hindsight-ai/hs-date-1), and the training data on [Hugging Face](https://huggingface.co/datasets/hindsight-ai/hs-date-1-data), all under MIT. If it gets a question wrong, [open an issue](https://github.com/vectorize-io/text2date/issues) with the question: that becomes training data for the next version.
