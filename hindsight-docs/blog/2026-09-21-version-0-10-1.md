Hindsight 0.10.1 adds a reranker that judges every candidate in a single question instead of one call each, and makes a bank something you can move: clone it in one call, export and import it with a defined scope, or rename it in place with its stored files following along. It also adds server-side time filtering to the memories and documents APIs, lets automatic mental-model refreshes run on their own LLM, and fixes a set of isolation, deadlock and provider bugs. **Everyone on 0.10.x should upgrade** — this release closes a cross-request tenant leak, two deadlocks and several ways a retain could be lost.

- [**A reranker that reads the whole pool at once**](#a-reranker-that-reads-the-whole-pool-at-once): The `typesafe` provider ranks all candidates in one question, and can optionally cut the irrelevant tail.

## A reranker that reads the whole pool at once

Set `HINDSIGHT_API_RERANKER_PROVIDER=typesafe` and recall's reranking runs on TypeSafe's Jev model (`jev-latest` by default). It isn't a `/rerank` endpoint: instead of scoring each candidate on its own, it is asked **one question with every candidate as an option**, and the answer is the ranking.

That is both more accurate and far cheaper, because judged together the model only has to say which candidate beats which, rather than pin each one to an absolute scale it re-derives on every call. On 200 LoCoMo questions with 30 candidates each:

|                                  | recall@1  | NDCG@10   | calls/query | $/1k queries |
| -------------------------------- | --------- | --------- | ----------- | ------------ |
| `local` MiniLM (current default) | 0.800     | 0.850     | 0           | free         |
| one call per candidate           | 0.865     | 0.927     | 30          | 0.40         |
| **whole pool in one question**   | **0.940** | **0.953** | **1**       | **0.07**     |

The gap widens at production-sized pools: at 240 candidates, one call per candidate takes 2.76s per query and one question takes 0.075s, at better accuracy. Pools larger than 255 candidates are ranked in rounds, with the winners ranked against each other.

**Cutting the irrelevant tail is opt-in.** Set `HINDSIGHT_API_RERANKER_TYPESAFE_PRUNE_CANDIDATES=true` and a second question asks how far down the shortlist relevance actually extends; everything past that point is dropped, so recall returns the relevant memories in order and nothing else. No threshold to tune — the model picks the depth, and at least one candidate always survives. On a real bank it cut 300 candidates to 3, which is exactly why it stays off by default: try it on your own data before turning it on.

Scores from this provider are **rank positions, not confidences** — a probability out of one pool says "best of these", not "relevant", and two pools aren't comparable. A score of exactly `0.0` means the backend judged the candidate past the cut.

Set the credentials with `HINDSIGHT_API_RERANKER_TYPESAFE_API_KEY`; `..._MODEL`, `..._BASE_URL`, `..._TIMEOUT` and `..._MAX_CONCURRENT` are there if you need them.

## Move a bank

A bank used to be somewhere your memories lived, not something you could pick up. Three changes in 0.10.1 make it portable:

- **Clone a bank** in a single API call instead of orchestrating an export and an import yourself.
- **Unified export and import** with an explicit transfer scope, so an archive says what it carries and an import puts it back the same way. Banks whose memories live in the memories store now export, import and clone correctly, and converted files and attachments survive the trip.
- **Rename a bank in place** with `hindsight-admin`. The bank's stored files move to the new prefix with it, so nothing becomes unreachable after the rename.

One migration ships with this release: attachments are now associated directly with their documents, replacing the separate `document_attachments` table. It touches only attachment bookkeeping, so it's quick on any size of deployment.

## Filter by time on the server

Listing memories or documents and then narrowing by date meant pulling pages you were going to throw away. Both APIs now take time filters and sort options directly, and the control plane's document list exposes them as presets (last 24 hours, last week, and so on) plus a custom range. Knowledge pages get an advanced search dialog on top of the same idea, and knowledge-page search scores are now normalized to a consistent 0–1 range, so a score means the same thing between queries.

## A separate LLM for mental-model refreshes

Automatic mental-model refreshes ran on whatever LLM the bank used for everything else. They're background work with different economics from a user-facing retain, so 0.10.1 lets you configure a provider and model for refreshes on their own — a cheaper model for the background pass, your usual one for the path a user is waiting on.

Two related controls landed alongside it: the reflection search-observation budget and which entities it considers are now configurable, and the default trigger for newly created knowledge pages can be set rather than being fixed.

## More work out of the same box

- **Retain on chunked documents** stops rebuilding the prompt and schema for every chunk of the same document.
- **Bank lists** are no longer slow on deployments holding many memory units.
- **Archive creation** doesn't block the event loop or hold a read transaction open for its whole duration, so exporting a large bank stops making everything else wait.
- **Recall** reuses observation source memory IDs through the pipeline instead of re-deriving them.
- **Startup fails fast** with a clear error when the configured API port is already in use, instead of failing obscurely later.

## Isolation and reliability fixes

- **Tenant information no longer leaks between requests** through shared extensions. If you run a multi-tenant deployment, this is the reason to upgrade.
- **Stored files are isolated per tenant** and are deleted when their bank is deleted, instead of lingering.
- **Two deadlocks are gone**: re-ingestion against observation cleanup, and same-bank cleanup against document updates.
- **Retain no longer drops requests** that hit a delete-race database conflict — it retries them.
- **Mental-model refreshes stop replacing a page's current state with older events.**
- **Recall refuses a missing bank properly** before returning a not-found response, and **reflect rejects blank queries** instead of spending an LLM call on them.
- **Hindsight API keys are redacted from memory-defense output**, and ordinary technical numbers are no longer mistaken for credit-card numbers and redacted.
- **Bank IDs that are too long or contain control characters are rejected.**
- **Recall's default temporal window uses UTC** regardless of the server's timezone, and PostgreSQL search matches meaningful query terms rather than the raw sentence.
- **Bulk memory deletion returns the correct `deleted_count`**, and setting the recall query token cap to zero now disables the cap as documented.

## Providers and platforms

- **Anthropic responses are no longer truncated** for callers that don't set an output cap.
- **Rate-limit recovery** works when a provider supplies retry timing as a number.
- **Apple Silicon**: MLX installs only on supported machines, the unreliable MPS acceleration path is off for local models, and the MLX reranker releases memory after each batch.
- **Windows**: local embeddings start correctly under uv-managed virtual environments.
- **Non-English content** keeps its original writing script when retained, and entity clustering is more accurate within a batch.
- The **control-plane UI is reachable** when the server is bound to a loopback address, and recall/reflect options there are simpler and documented inline.
