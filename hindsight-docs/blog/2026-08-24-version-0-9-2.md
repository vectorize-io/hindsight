A knowledge page could come back from a refresh with a table welded onto one line, in a section nothing had edited, and never recover. The refresh that did it could run 6,000 times a day on a model whose scope had not changed. Both are fixed in Hindsight 0.9.2, along with pages that kept asserting facts the memory no longer held. Around that: retain stops allocating in proportion to the document it reads, recall takes a time window instead of parsing one out of your query text, and per-bank vector indexes are earned by size rather than created three at a time. **Upgrade** — the page damage is permanent once written.

## Recall: supply the time window yourself

- **A `temporal_window` on the request.** `RecallRequest` takes one, with a `start` and an `end`. Set it and that range is used verbatim — the natural-language date extraction is skipped entirely. Previously the only way to constrain time was to phrase it in English inside the query text and hope the parser agreed with you, which a date picker or an agent that had already resolved "last quarter" had no reason to do. Skipping the extraction also removes up to ~1.3s of pure CPU work on document-sized query text, which is exactly the shape of query consolidation and reflect issue internally.
- **Long queries keep their most selective terms.** Native BM25 previously scored every term in a paragraph-length query equally, so common words dominated and the query took a `ts_rank_cd` pass over every match. Recall now keeps the selective terms.
- **The result budget reaches the vector index.** A recall's budget is now applied down through vector search instead of being enforced only after the fact, so a large request stops over-fetching.
- **An over-budget fact is skipped, not a stop signal.** Hitting one fact too large for the remaining budget used to end the result assembly there, discarding every good match behind it. It's now skipped, and recall never answers a match with empty content.
- **A lone four-digit number is not a year.** `2024` in a query is no longer read as a date, so part numbers and error codes stop silently narrowing results to a decade.
- **The observation graph arm stays off nested-loop plans**, removing a stall on graph-heavy recalls.

## Retain: a memory budget instead of the whole document

Retaining a large document used to cost memory in proportion to its size, most of it spent before a single fact existed. Sizing a 45 MB body allocated 385 MB — building an 11.6-million-element list of boxed integers to return one number — and chunking it allocated another 200 MB by materialising every chunk up front. Both are now flat across 4, 16, 45 and 90 MB documents: 9.6 MB and effectively zero.

- **A memory ceiling you set in bytes.** `HINDSIGHT_API_RETAIN_MEMORY_BUDGET_MB` (default `128`) caps how much extracted-but-unwritten state one retain may hold. `HINDSIGHT_API_RETAIN_CHUNK_BATCH_SIZE` bounds how many chunks are in flight but not what they weigh — a chunk carries however many facts the extractor found in it — so this is the figure to size a worker against, multiplied by your concurrent retain slots. Over budget, extraction waits for the write path to catch up instead of growing. `0` restores the old count-only bound.
- **An oversized document is hashed once.** Every slice of a split document carried the identical body and re-sanitized and re-hashed the whole thing to derive a value the previous slice had already derived — around 18 minutes of a large retain spent proving one hash.
- **Chunk boundaries are unchanged.** Chunking no longer depends on langchain at runtime, which also drops `langchain-core` and `langsmith` from the install. The replacement is pinned against langchain's output across every separator tier by a differential test, because a shifted boundary would silently re-chunk every stored document.

## Knowledge Pages: full CRUD over MCP

- **Full Knowledge Base CRUD over MCP.** Creating, reading, updating and deleting Knowledge Pages are now native MCP tools, so an agent can maintain its own wiki without going through the REST API.
- **Refresh triggers are visible.** Each page's refresh trigger now appears in the tree view, so you can see what causes a page to rebuild without opening it.
- **A trigger update no longer resets the page.** Creating or updating a page patches its refresh trigger instead of replacing it, and a page's scope now lives on its mental model, so a trigger edit can't quietly drop the scope or the mode you configured.
- **Staleness is answered per scope**, not from a single bank-wide watermark, so a page covering one project no longer reads as stale because an unrelated part of the bank moved.
- **Concurrent tree writes are serialized**, closing a path where two simultaneous edits could corrupt the page tree.

## More model control: Copilot, Ollama, Voyage, Azure

- **A GitHub Copilot provider.** Set `HINDSIGHT_API_LLM_PROVIDER=github-copilot` to run Hindsight's LLM lanes on a Copilot subscription — no API key required.
- **Asymmetric embedding prefixes.** Many embedding models expect a different instruction prefix for a query than for a stored passage. You can now set `HINDSIGHT_API_EMBEDDINGS_QUERY_PREFIX` and `HINDSIGHT_API_EMBEDDINGS_PASSAGE_PREFIX` independently for text-in providers, and Voyage's built-in asymmetric behaviour is preserved rather than flattened.
- **Ollama honours your context length.** Free-form Ollama calls now go to the API that actually applies `num_ctx`, so the context window you configured is the one you get.
- **Consolidation uses your temperature.** The configured temperature is now forwarded to consolidation calls instead of being dropped.
- **Fewer provider surprises.** Automatic cache affinity is off for Azure OpenAI, where it caused routing errors; Vertex AI's EU and US regional endpoints work again; batch retain runs through a batch-capable model member; and a missing llama.cpp is reported plainly instead of looping on connection errors.

## Mental models: refreshes that stop degrading the page

The refresh path got the deepest work in this release.

- **Refreshes stop degrading page formatting.** A page could come back with a table welded onto a single line, in a section no delta operation had named, and never recover. The full refresh stored the model's markdown verbatim but derived the page structure from it with a typed-block parser that flattened anything it couldn't express — nested lists, list continuation lines, blockquotes, hard line breaks, horizontal rules, HTML, indented code, table alignment. Every loss was permanent, and the next delta refresh published the degraded copy over the whole document. Blocks are now stored as verbatim markdown fragments: nothing parses a table, so nothing can flatten one.
- **Delta edits address blocks by id.** They used to be addressed by index, which the model had to count. An off-by-one landed in range, silently overwrote an unrelated block, and was recorded as a success. An id is copied rather than derived, and one that doesn't resolve — or that names a block in another section — is skipped and reported instead of applied to the wrong place.
- **Facts that no longer exist get unsaid.** A page kept asserting facts that had been invalidated or deleted. Nothing could notice: a vanished row raises no watermark, so neither the consolidation trigger nor the cron loop ever saw the removal, and on a quiet bank the page stayed frozen on what it last said. A refresh now derives the retracted set — the citations it holds, minus what's still live — and removes those claims. Retired fact ids also stop appearing in the control plane's provenance dialog.
- **`last_refreshed_at` means the refresh again.** It had come to hold the source-data watermark, which is clamped so it can never regress — so on a model whose scope gained nothing, a refresh wrote the stored value back over itself. The document was rewritten and the timestamp never moved, and a client asking "have I already refreshed this?" refreshed it again on every tick: one reporter drove ~6,000 refreshes a day against an intended ~350. `last_refreshed_at` is wall-clock once more, stamped on every refresh that completes, and a new `last_memory_seen_at` carries the watermark. If you test staleness by comparing a model against `last_memory_write_at`, compare it to `last_memory_seen_at` — that is the side that stands still while a model's scope is quiet.
- **A floor on automatic refreshes.** `HINDSIGHT_API_MENTAL_MODEL_MIN_REFRESH_INTERVAL_SECONDS` sets a minimum gap between two automatic refreshes of the same model, overridable per bank and per model. A trigger that fires early isn't dropped — its refresh is parked until the window closes and every further trigger folds into it, so a burst of small retains costs one refresh instead of one each. Explicit refreshes ignore the floor. The default is `0`, so nothing changes until you set it.
- **At most one queued refresh per model.** A bank whose queue drained slower than it filled accumulated one refresh per model per consolidation round — in one case 12,000 pending operations across 259 models, roughly 45 identical copies each, every copy a full recall plus an LLM call once it ran. A submit for a model that already has a queued refresh now folds into it.
- **A refresh reports what it did.** Every refresh operation now carries a typed `outcome` — and a `failure_reason` when it fails — on the operations list and the single read. A rewrite, a delta that changed nothing, a fallback and an outright failure used to be indistinguishable after the fact. Refresh operations also name their `mental_model_id`, which the list previously couldn't tell you.
- **Reflect can't overwrite a model with a placeholder.** A run that produces no answer now fails instead of storing its "no answer" text, which could land on top of a mental model that had real content in it.
- **Per-model staleness in the control plane**, described the same way everywhere it appears, and the mental-model and directive list endpoints report real totals so pagination works.

## Thousands of banks: indexes earned by size

If you run Hindsight with thousands of banks, this release changes what that costs.

- **Vector indexes are earned, not assumed.** Every per-bank vector index lives on the shared memories table and is planned against by every _other_ bank's queries — so creating three per bank puts a ceiling on how many banks you can have. Set `HINDSIGHT_API_VECTOR_INDEX_MIN_ROWS` (try `10000`) and a bank gets an index for a fact type only once it holds enough memories to need one; smaller banks use exact search, which is both faster and exact. The default stays `0`, meaning off, so existing deployments behave exactly as before.
- **Sweeps sized to your deployment.** Cross-tenant maintenance sweeps now scale with the number of tenants instead of doing constant per-tenant work, the retention sweep runs in batches rather than one long transaction that stalls foreground queries, and maintenance skips a schema under concurrent schema change instead of deadlocking against it.
- **A lighter worker loop.** Background workers use one pooled database connection per poll cycle with a single statement of session setup, cutting steady-state overhead on an idle deployment.
- **A paginated bank list**, so listing banks stays workable as their number grows.
- **Traced background work.** Worker runs are traced and join the caller's trace, so an async retain is visible end to end instead of disappearing after the API returns.
- **Bank config is saved atomically.** Configuration is validated and persisted as one unit, so a rejected value can't leave a bank half-updated.

0.9.2 also carries a round of fixes to what gets stored. Re-retaining content now deletes the chunks the edit removed, instead of leaving them behind and recallable. Merging observations preserves their original dates, and memory timestamps are stamped on every write that changes a memory, so recency ranking reflects reality. Entities are no longer merged on resolution history alone. Secret redaction uses ASCII token boundaries, so a key sitting next to CJK text is masked like any other. Fact extraction retries and then fails loudly on a drifted schema rather than quietly extracting nothing, a malformed memory-defense policy fails the retain instead of skipping screening, and a provider content-policy refusal is treated as the permanent outcome it is. Batch recovery is scoped to the account that submitted the batch, embedding config inherits your unset LLM settings instead of overwriting them, the CLI exits non-zero on an invalid API URL and drops ANSI color when it isn't attached to a terminal, and the control plane keeps your memories search open when you clear the query.
