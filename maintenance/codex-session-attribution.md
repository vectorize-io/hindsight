# Codex Session Attribution

Part of the root [maintenance contract](../MAINTENANCE.md).

## Intentional Divergence

The standalone Codex client at fork base `c7c4be93ec7411feaf448233b5d7d2b12c3f60c9` omitted the item's named retain strategy. On a shared bank with no default strategy or retain mission, session content therefore used generic extraction. The retained patch selects an explicitly configured strategy and adds source interpretation context only for `agent-session`. It does not define or provision another bank mission.

Upstream guidance was checked at `ec39e10900c6a971f1a73cd37402228d5cccaa25` on `2026-10-01`, including root AGENTS.md, CLAUDE.md, CONTRIBUTING.md and the code-review standards. The independent approach was to extend existing configuration and item serialization, preserve role-bearing source text, and leave shared bank defaults alone. Related [issue #2551](https://github.com/vectorize-io/hindsight/issues/2551) concerns ambiguous surrounding source. Open [PR #4751](https://github.com/vectorize-io/hindsight/pull/4751), inspected at `339b165860e587a6af40fb9be3021923038e60f9`, adds source lookback but explicitly leaves wider speaker and quoted-author attribution open. Closed [PR #3867](https://github.com/vectorize-io/hindsight/pull/3867) proposes opt-in transcript hygiene in the newer coding-agents package. Neither replaces this standalone client request boundary. No server prompt, routing or language-control change is part of this patch.

- **Coupled Surfaces:** `retain.py`, the shared `lib/bank.py` mission helper, `lib/client.py`, `lib/config.py`, settings and the Codex README. A selected strategy must not cause the installer's legacy missions to overwrite a preprovisioned shared bank, including through recall. SessionStart currently performs no mission update. Default-null behavior remains compatible.
- **Strategy Ownership:** The destination bank's configuration owner must maintain and review `agent-session`. Stronger canonical mission wording belongs with that owner, not in another Codex mission registry. Read back the intended bank before enabling selection. Model interpretation still needs extraction-quality verification and may need surrounding source to resolve ambiguity.
- **Source Cases:** The curation project's targeted source labels independently identified anonymous-video speaker transfer (`2e0ef050-cd34-4dec-b165-65a338ec6e88`), lead/subagent actor transfer (`32679ca0-0654-4c37-9986-5b99d54dcf8a`), tentative opinion promoted to a decision (`01d80f08-194a-45b6-b266-c591c8006acd`), open PR promoted to merged (`61b2069c-3ce9-4985-8db9-573212ff09c4`), and assistant guidance promoted to user preference (`3a1f2d6d-1d61-405b-9d33-5030279bdc43`). These are targeted cases, not a population prevalence estimate. The regression uses synthetic equivalents, not benchmark or holdout material.
- **Regression:** Run `uv run --no-project --with pytest --with tiktoken==0.12.0 pytest hindsight-integrations/codex/tests -q`. Client tests inspect item-scoped HTTP requests. Hook tests exercise actual Codex response-item input, preserve roles and qualifications in both JSON and text formats, reject invalid config before requests, prevent bank-wide PATCH from retain, recall and SessionStart for explicit strategies, retain the legacy default route, and prohibit fallback after a strategy rejection. Deterministic checks prove request construction and prompt delivery, not real-LLM attribution fidelity.
- **Adopt Or Retire:** Retire this compatibility patch when the active integration selects an equivalent reviewed session strategy and passes source-role, status and isolation checks. Rollback restores the standalone client's legacy request route, without changing bank configuration or deleting historical facts. Installation and bank selection need separate runtime verification after source delivery.
