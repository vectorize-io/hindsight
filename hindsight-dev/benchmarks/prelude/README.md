# Prelude retrieval eval

A deterministic baseline for **reflect's forced hierarchical prelude** — the
opening walk through mental models → observations → recall that happens before
the agent gets free choice.

## Why this exists

We had no way to tell a retrieval change from a retrieval regression. The
question that prompted it (#3865 / PR #4066): the prelude used to spend one
forced LLM turn per layer, so each layer's query was written having *read* the
layers above it. Planning all the queries up front makes them **cold**. And
because the mental-model result feeds the deterministic short-circuit that
decides whether the lower layers run at all, a cold query can change the entire
evidence set — not just one search.

That is not settleable by argument, and end-to-end suites bury it under
synthesis noise. This measures it directly.

## The corpus

Authored, never extracted. Every stored row's text is byte-identical to the
YAML, which is the only reason gold labelling is possible: a corpus generated by
a real LLM has no stable ids to label and no way to separate a retrieval
regression from an extraction one.

- `corpus/facts.yaml` — raw world facts, deliberately full of **near misses**.
  Every answerable question has plausible-but-wrong neighbours; `distractor_for`
  records which question each one competes with. A corpus of unrelated facts
  scores 1.0 for any query and measures nothing.
- `corpus/layers.yaml` — observations and mental models. `stale: true` is not a
  column, it is **ordering**: staleness is derived from whether in-scope memories
  arrived since the model's last refresh, so stale models are created before the
  facts and fresh ones after.
- `corpus/questions.yaml` — questions grouped by which layer *should* answer:

  | category | the correct behaviour |
  |---|---|
  | `mm_only` | a fresh mental model answers; descending is wasted work |
  | `mm_stale` | the mental model is confidently **wrong**; the run must descend |
  | `observations_only` | no mental model covers it, a consolidated observation does |
  | `raw_facts_only` | the answer is a specific value no summary carries |
  | `multi_layer` | the frame is in an observation, the specifics only in raw facts |
  | `near_miss` | answerable, but surrounded by close neighbours |
  | `absent` | the bank does not hold it; retrieving nothing relevant is correct |

## Metrics

Scored **by rank, within each layer**. Two traps this avoids:

- *Set membership saturates.* "Was the gold id returned at all" is 1.0 for every
  query as soon as the corpus is smaller than one recall page.
- *Flat ranking is meaningless.* Concatenating the layers scores every raw fact
  behind every mental model no matter how good the query was. A fact competes
  with other facts.

So: `recall@3` (gold inside the top 3 of its own layer) and `MRR` (how far down
the reader must go for the first hit), plus the **short-circuit fire rate**,
which is reported separately because the mental-model query decides it.

## Running it

```bash
./scripts/benchmarks/run-prelude-eval.sh
# or
cd hindsight-dev && uv run python -m benchmarks.prelude.floor_ceiling --json out.json
```

Needs no API key — the corpus is built with the `mock` provider and neither arm
calls an LLM.

## Tier 1 (built): floor vs ceiling

- **floor** — every layer searched with the user's question verbatim. Not a
  strawman: this is exactly what the prelude falls back to when planning fails.
- **ceiling** — the hand-written `ideal_query`, the best a planner could do.

Both are deterministic, so the gap is attributable to wording alone. First run:

```
recall@3  floor=0.929  ceiling=1.000  gap=+0.071
MRR       floor=0.762  ceiling=1.000  gap=+0.238
```

Wording moves retrieval, mostly through **rank** rather than presence. The
largest single mover is the `mm_stale` question (0.50 → 1.00), which is the case
where a wrong mental model has to be superseded by raw facts.

## Tier 2 (not built): where does a real planner land?

Run the prelude both ways with a real LLM, N times per question, and report
distributions — where the planner falls between floor and ceiling. Paired on the
same corpus and model, so most provider noise cancels. Do not put this in CI.

## Two findings this already surfaced

1. **A created-but-never-refreshed mental model is always stale.** Staleness
   resolves from the refresh stamps, and a model with no stamp is reported stale
   unconditionally. It can therefore never short-circuit the forced descent until
   something refreshes it once.
2. **One stale model suppresses the short-circuit for all of them.** The rule
   requires *every* returned mental model to be fresh, so an unrelated stale
   model in the top-5 keeps the descent going even when a fresh model answers the
   question outright. This is why `q-answer-style` reports a short-circuit
   mismatch — the eval is right and the corpus is doing its job.

Neither is a bug this harness introduced; both are behaviours nothing was
measuring before.
